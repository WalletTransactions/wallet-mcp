# Design

## D1. `text` — только массив

Валидатор схемы знает простые типы (`string`, `integer`, `array`), объединения
«строка или массив» в нём нет, а `type: ["string", "array"]` хуже читается
маленькой моделью. Массив — как у `categories`/`wallets`, модель его уже
умеет. Элемент проверяется по `items.maxLength` (валидатор теперь проверяет
элементы массива строк по схеме `items`). Пустые после trim варианты и
повторы отбрасываются; все пустые — фильтра по тексту нет.

## D2. Объединение — в SQL, не в сервисе

Варианты уходят в `/api/reports/operations` повторённым `q`
(wallet-report `search-text-variants`, wallet-api 000032). Сервис не делает
N вызовов и не складывает итоги: операция под двумя вариантами посчиталась
бы дважды, а инвариант сервиса — суммы считает SQL.

## D3. Курсор — одна строка `«дата|uuid»`

wallet-report отдаёт `next_cursor_date`/`next_cursor_uuid`; модели проще
переслать одно значение. Разделитель `|` не встречается ни в timestamp, ни в
uuid. Форма проверяется до запроса (дата `ГГГГ-ММ-ДД` + цифры/пробел/`T`/`:`/`.`,
не длиннее 26; uuid 8-4-4-4-12), иначе `isError`
«cursor неверен: передайте next_cursor из прошлого ответа без изменений.» —
без проверки битый курсор дал бы 400 wallet-report и модель увидела бы
«Отчёты временно недоступны». `has_more: true` без полей курсора — ответ не
по контракту → «Отчёты временно недоступны».

Курсор не привязан к фильтрам: с другими аргументами он даст другой набор
(как и у wallet-report). Описание просит передавать те же аргументы.
