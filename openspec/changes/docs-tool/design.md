# Design

## Context

wallet-mcp — чистый исполнитель инструментов: токен клиента меняется в google-auth на
короткий JWT для wallet-report (`wmcp_…` через `/internal/mcp/token`, JWT через RFC 8693),
JWT кешируется по хэшу токена. wallet-docs отвечает по OpenSpec-спекам на
`POST /api/docs/ask`, но принимает только JWT с `aud` ∋ `wallet-docs`, `scope` ∋
`docs:ask` и выбирает область по `role` и `platform`. Change `docs-audience` (google-auth,
в архиве) выдаёт этот адресат только пользовательским токенам Android и web; токены обмена
и MCP-токены его не получают. См. proposal.md.

## Goals / Non-Goals

**Goals:**
- Модель MCP-клиента может спросить «как это работает» и получить ответ с источниками.
- Фича необязательна: нет `WALLET_DOCS_URL` — нет инструмента, всё прочее без изменений.
- Права не расширяются: MCP видит не больше, чем web-пользователь, и не видит админских спек.

**Non-Goals:**
- Индексация документации (она в wallet-infra, `docs-index`) и сам поиск (wallet-docs).
- Выбор модели ответов и качество справки — задача 6.3 change'а `docs-service`.
- Новые инструменты данных, запись, пересказ данных кошелька в справке.

## Decisions

**D1. wallet-mcp ходит в wallet-docs напрямую, не через гейтвей.** Так же, как в
wallet-report (`WALLET_REPORT_URL`). Через гейтвей нужен пользовательский JWT с
`aud` ∋ `wallet-docs`, которого у MCP нет; лишний переход и лишний путь для аутентификации.
Альтернатива «пустить `/api/mcp/` справку через гейтвей» отвергнута.

**D2. Отдельный JWT для wallet-docs, а не общий с wallet-report.** `aud` = `wallet-docs`,
`scope` = `docs:ask`, `exp` 300 с, кеш отдельный, по хэшу токена. Альтернатива — добавить
`wallet-docs` в уже выдаваемый JWT для wallet-report — отвергнута: это раздало бы адресата
каждому вызову инструмента данных, нарушив принцип `docs-audience` D2/D3 (адресат отвечает
за «куда», scope — за «что можно»), и сделало бы справку невыключаемой. Цена — второй
обмен на первый вопрос в сессии.

**D3. Правки google-auth — отдельный change `docs-mcp-audience`.** (а)
`POST /internal/mcp/token` принимает необязательный `audience` из белого списка
(`wallet-report` по умолчанию, `wallet-docs`); без поля поведение прежнее, `scope` — из
таблицы. (б) Таблица политики обмена получает пару «actor `wallet-mcp` — subject с
`aud` ∋ `wallet-mcp`, `scope` ∋ `mcp:read` → `audience` `wallet-docs`, `scope`
`docs:ask`». JWT по `wmcp_…` несёт `platform` = `mcp`; JWT обмена, как и сейчас
(`add_exchange_claims`), наследует `platform` исходной сессии; `role` не несёт ни один.
Отдельный change, а не
правка архивного `docs-audience`: тот описывает пользовательский токен и уже выкачан.

**D4. Правка wallet-docs — отдельный change `mcp-scope`.** `scope_for`: платформа
`mcp` → `wallet-web`, `wallet-web-eqdefault`, `wallet-mcp`, виды только `spec`; роли у
токена нет, поэтому админом он не станет даже у администратора (как в `mcp-tokens`:
«JWT обмена без роли»). Расширение таблицы — код и тест, не настройка (design D5
wallet-docs). Чат wallet-ai идёт путём обмена и наследует `platform` исходной сессии:
пользователь Android в чате видит область Android, веб — область web; строка `mcp`
нужна только клиентам с `wmcp_…`.

**D5. Инструмент условный и статичный на процесс.** `WALLET_DOCS_URL` читается при
старте; пустой — `tools/list` без `ask_docs`. Это сохраняет модульность («нет компонента —
нет фичи»), как у `docs-route` в гейтвее. Динамическая проверка живости wallet-docs в
`tools/list` отвергнута: статус не должен менять список инструментов между вызовами.

**D6. Ответ wallet-docs возвращается как есть.** `answer` и `sources` — без правки и без
добавления собственных ссылок: сервис не интерпретирует спеки и не подмешивает данные
кошелька, а модель MCP-клиента видит те же источники, что пользователь. Формат JSON в
текстовом элементе — как у остальных инструментов.

**D7. Ошибки справки — `isError`, а не HTTP-ошибка запроса.** Недоступная справка не
должна ломать чат с вызовами инструментов данных в той же сессии. Входящий токен
по-прежнему проверяется до вызова инструмента (`mcp-access`). Тексты — в спеке дословно.

**D8. Таймаут ответа короче таймаута гейтвея.** Гейтвей ждёт MCP 30 с; ответ 8B-модели
на видеокарте с 8 ГБ может идти заметно дольше. Чтение ответа wallet-docs ограничивается
25 с (соединение 3 с); по таймауту — «Справка временно недоступна, попробуйте позже.»
Значения уточняются замером в задаче 3.4.

Замер 2026-11-13 (test, `wallet-parse` в LM Studio, через гейтвей, токен `wmcp_…`):
10 вопросов — 9 ответов за 3.2–8.1 с, p50 6.0 с, p95 8.1 с; ещё 6 вопросов
раньше — 4.2–9.2 с. До порога 20 с запас большой, таймауты 25 с и число
фрагментов не меняются. Один вопрос («Как работает импорт выписок?») вернул
«Справка временно недоступна»: LLM wallet-docs ответила `http_400` (видимо,
контекст LM Studio), wallet-docs отдал `503` — это качество справки (задача
6.3 `docs-service`), а не wallet-mcp.

**D9. Лимит wallet-docs (6 вопросов в минуту на `sub`) общий.** `sub` у MCP-JWT тот же, что
у веб-сессии пользователя: ведро общее. Принято: справка редкая, а `Retry-After`
сообщается модели в тексте ошибки, чтобы она не зацикливалась.

## Risks / Trade-offs

- **Выбор инструмента маленькой моделью.** Чат wallet-ai (gemma-4-e4b, 8 ГБ) получает
  восьмой инструмент: схема занимает токены контекста, модель может звать справку вместо
  инструмента данных или наоборот. Смягчение: описание прямо разделяет «как работает» и
  «сколько потрачено»; проверка на живой модели в задаче 4.2.
- **Качество справки.** По замеру 2026-11-13 около 14 из 20 ответов верны, часть вопросов
  получает ложный отказ — задача 6.3 `docs-service`. Инструмент передаёт ответ как есть,
  поэтому его качество не лучше качества wallet-docs.
- **Выкатка в нужном порядке.** До выкатки google-auth `docs-mcp-audience` обмен для
  wallet-docs отвечает `400`, до `mcp-scope` в wallet-docs — `403`; оба случая дают
  «Справка недоступна для этого токена.», остальные инструменты не затронуты.
  Поэтому `WALLET_DOCS_URL` включается в окружении последним.
- **Общий `sub` и лимит.** Вопросы модели и пользователя в вебе делят 6 в минуту.
- **Утечка спек через модель.** Область определяет wallet-docs по JWT, а не клиент;
  у инструмента нет аргументов области. Остаточный риск — модель пересказывает ответ
  пользователю с большим доступом, чем у токена; для web-области это допустимо.

**Правки в других сервисах:** google-auth (D3), wallet-docs (D4), wallet-infra
(`WALLET_DOCS_URL`, проверка `wallet-mcp` в списке индекса). wallet-gateway, wallet-api,
wallet-report, wallet-web и wallet-common — без изменений.

**Какой эндпоинт вызывает инструмент.** Единственный: `POST {WALLET_DOCS_URL}/api/docs/ask`
(wallet-docs). Итог вычисляет не модель и не wallet-mcp, а wallet-docs по найденным
фрагментам; сумм и дат инструмент не считает.
