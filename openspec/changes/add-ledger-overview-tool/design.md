# Design

## Context

Сервер MCP исполняет детерминированные инструменты, модель приносит клиент. Сегодняшняя
дата и правила уже лежат в `instructions` ответа `initialize`, и Claude Code их использует.
LM Studio и часть других клиентов `instructions` модели не показывают, а описания
инструментов из `tools/list` до модели доходят всегда. Поэтому локальная модель
`wallet-parse` (8B, Q4) не знает ни даты, ни периода данных, не вызывает инструменты и
переспрашивает годы, даже когда системный промпт с датой задан вручную.
Второй симптом: Claude Code сам выбрал период 36 месяцев и получил `avg_per_month` по
пустым месяцам (в 3 раза ниже настоящего). Сервис не знает, где в леджере начинаются данные.

## Goals / Non-Goals

**Goals:**
- Вопрос без периода получает ответ за период данных без уточнений у пользователя.
- Подсказка доходит до модели в любом клиенте (через описания, а не только `instructions`).
- Один дешёвый вызов без аргументов и без возможности ошибиться.

**Non-Goals:**
- Не гарантировать, что любая модель вызовет инструмент: это задача модели и клиента. Мы лишь убираем причину «не знаю период».
- Не добавлять инструменты записи и не менять расчёты `avg_per_month`.
- Не считать суммы в сервисе: итоги по-прежнему считает SQL wallet-report.

## Decisions

**Один инструмент `ledger_overview`, а не новые аргументы у существующих.** Альтернатива
— сделать `from`/`to` необязательными и подставлять период данных по умолчанию. Отвергнуто:
пропал бы принцип «период передаётся явными датами», а в ответе с `period` модель уже
привыкла видеть эхо условий. Отдельный вызов к тому же даёт модели `default_currency`
и список кошельков, о которых она иначе узнаёт ещё одним вызовом `list_wallets`.

**Период данных ограничен 36 месяцами.** `spending_by_category_by_month` не принимает период
длиннее 36 месяцев (так в `wallet-tools`), поэтому `data_period.from` не уходит дальше
36 месяцев назад и начинается с первого числа месяца. Так `avg_per_month` не усредняется по
пустым месяцам до первой операции, как при периоде 2023-12 для данных с 2025-12.

**Источник первой даты — новый эндпоинт wallet-report `GET /api/reports/data-range`.**
Существующий `/api/reports/operations` отдаёт страницы по убыванию даты с курсором, и найти
первую операцию можно только обходом всех страниц. Эндпоинт возвращает
`{"first_date","last_date","operations_count"}` одним `SELECT min(date), max(date), count(*)`
по живым операциям леджера пользователя (у пустого леджера даты `null`, количество `0`).
Модель сумм не считает: `operations_count` и даты — это факты из базы, а не расчёт.
Правка в другом сервисе: wallet-report, отдельный change с `openapi.yaml`; мост между ними
контракт «поля и семантика выше». wallet-api, google-auth, gateway и wallet-common не меняются.

**Подсказка в описаниях инструментов, а не только в `instructions`.** Фраза «Период не
назван — сначала вызови ledger_overview.» стоит в начале описания каждого инструмента с
периодом: она доходит до модели в любом клиенте и стоит там, где модель решает, чем
заполнить `from`/`to`. В `instructions` строка добавлена тоже, для клиентов, которые их
показывают. Альтернатива — менять промпт клиента (LM Studio): не наш слой, и не работает
для чужих клиентов.

**Ответ из двух запросов к wallet-report, параллельно.** `data-range` и `accounts`
(`balance` не нужен: сумм в ответе нет). Валюта по умолчанию — валюта первого кошелька, как в
требовании «Валюта эквивалента». При ошибке любого запроса — `isError`, частичный ответ не
возвращается.

## Risks / Trade-offs

- [Модель всё равно не вызовет `ledger_overview`] → описание начинается с прямой команды, `hint` в ответе повторяет правило; если и этого мало, остаётся менять модель или промпт клиента. Проверка — живая сессия в LM Studio.
- [Период данных короче реальной истории при истории больше 36 месяцев] → документировано в спеке; `operations_count` показывает полный объём, длинные периоды модель может запросить явными датами.
- [Одна лишняя сетевая поездка на каждый вопрос] → два параллельных запроса к SQL-агрегату по индексу даты; кеш не нужен.
- [wallet-mcp нельзя выкатить раньше wallet-report] → порядок выкатки зафиксирован в tasks.md: сначала wallet-report, потом wallet-mcp; без эндпоинта `ledger_overview` отвечает `isError`.
