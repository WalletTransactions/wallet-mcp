# Proposal

## Why

Вопрос «сколько потратил на стрижку в 2026 и когда стригся последний раз» сегодня
не закрывается одним вызовом `search_operations`. Живой пример (2026-11-18): поиск
по `text: ["стриж", …]` вернул три операции, в том числе «Машинка для стрижки
волос» (62,10 € в Electronics), которая не стрижка, а `total` оказался 95,10 € вместо
33,00 €. Чтобы получить верную сумму, пришлось вторым вызовом сузить поиск до
`Personal Care`. Но тогда любые «стрижки» в другой категории (например, в «Красота и
уход») были бы потеряны молча. Даты «первая/последняя» модель берёт из страницы,
а интервал между событиями считает сама — а модель не должна считать.

Цель — чтобы ответ поиска сам показывал, в каких категориях нашлось совпадение,
позволял отсечь ложные срабатывания по тексту и давал готовые даты и интервал.

## What Changes

- `search_operations` получает необязательный аргумент `exclude_text` — массив
  вариантов подстроки (1..10, каждый до 100 символов): операция, чей комментарий
  содержит ЛЮБОЙ из них, не попадает ни в страницу, ни в `total`/`count`.
- В ответе `search_operations` при любом фильтре (там же, где сегодня `total`) появляется
  блок `summary`: `first_date`, `last_date` по ВСЕМ подходящим операциям периода,
  `avg_interval_days` (среднее число дней между соседними подходящими операциями;
  только при `count` ≥ 2) и `by_category` — `[{category, count, total}]`.
- Если заданы и `text`, и `categories`, в ответе появляется `other_matches` —
  `[{category, count, total}]` по категориям вне `categories`, где комментарий
  тоже совпал с `text`. Пусто, если таких нет (поле есть, массив пустой — чтобы
  модель видела «проверено»).
- **Нужна правка wallet-report** (см. design): `GET /api/reports/operations`
  принимает `exclude_q` и `summary=true` и отдаёт `summary` и `other_matches` из SQL.
  Без неё wallet-mcp пришлось бы суммировать сырые строки, что запрещено инвариантом.
- README.md (таблица инструментов) и описание инструмента в `tools/list` обновляются.

Ломающих изменений нет: новые аргументы необязательны, новые поля ответа аддитивны.

### Modified Capabilities
- `wallet-tools`: требование `search_operations` (новый аргумент `exclude_text`), новые
  требования «Сводка поиска» и «Совпадения вне фильтра категорий».

## Impact

- **wallet-mcp**: `src/tools.cpp` (схема аргументов, `search_operations`), описание
  инструмента, `tests/test_tools.cpp`, `tests/test_mcp*.cpp`, `scripts/smoke.sh`, README.md.
- **wallet-report** (сопутствующий change): `openapi.yaml`, SQL/хендлер `/api/reports/operations`,
  его тесты. Новые параметры необязательны — `wallet-web` и `android-wallet` не затронуты.
- google-auth, wallet-gateway, wallet-api, wallet-infra, wallet-common — без изменений.
- Порядок выкатки: сначала wallet-report, затем wallet-mcp (старый wallet-report
  без `summary` — wallet-mcp должен отвечать как раньше, без блока, а не падать).
