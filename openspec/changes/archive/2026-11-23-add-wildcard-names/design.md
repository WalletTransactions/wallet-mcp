## Context

Проблема и мотивация — в `proposal.md`. Что есть сейчас:

- Имена кошельков и категорий разбирает `resolve_all` (`src/tools.cpp`) через
  `text::resolve_name`: точное совпадение, затем уникальный префикс. Не нашлось
  — `ToolFailure` со списком всех имён этого вида.
- Логика инструментов опирается на присутствие параметра: `has(args,
  "categories")` решает, будет ли `similar`, `by_month`, откуда брать `total`.
- `search_operations` делает один `GET /api/reports/operations`; при любом
  фильтре wallet-report отдаёт `total_eq`, `total_count` и `summary`.

## Decisions

### D1. `"*"` снимается на входе, а не в `resolve_all`

`tools::call` после проверки схемы копирует аргументы и удаляет `wallets`,
`categories`, `exclude_categories`, если в массиве есть `"*"`, и `wallet`,
если он равен `"*"`. Дальше инструмент видит вызов без параметра, и все
проверки «задан ли параметр» работают как при его отсутствии.

Если вернуть из `resolve_all` пустой список, `has(args, "categories")` всё
равно был бы истинным, и `spending_by_category` отдал бы пустые строки, а не
полную разбивку.

Только `"*"`, без «все»/`all`: эти слова могут быть именами настоящих
кошельков или категорий, а `"*"` именем быть не может.

`check_category_lists` («categories или exclude_categories, не оба») идёт
после снятия: `categories: ["*"]` вместе с `exclude_categories` — допустимый
вызов «все, кроме».

### D2. `outside_wallets` — второй запрос с `limit=1`

Условие: задан `wallets`, нет курсора, `total_count` ответа 0. Тогда тот же
запрос (фильтры, `kind`, `q`, `exclude_q`, период) уходит без `wallet_uuid`,
с `limit=1` и без `summary`. Из ответа берутся `total_count` и `total_eq`.
Нужны только итоги: их wallet-report считает по всем подходящим операциям,
страница не важна.

Почему не всегда: при найденных операциях фильтр сработал и подсказка не
нужна; на следующих страницах первая страница уже не пустая.

Без `summary`, потому что без фильтра (когда `wallets` был единственным)
сводки по всему периоду не нужно, а итог wallet-report отдаёт только при
фильтре. Поэтому, если кроме `wallets` фильтров нет (`kind: "any"`, без
`text` и категорий), второй запрос итога не даст, и поля не будет.

Отказ второго запроса (`ReportsDown`) не превращает успешный ответ в ошибку:
подсказка просто не добавляется.

## Risks / Trade-offs

- [Лишний запрос к wallet-report] → Только при пустом результате с `wallets`,
  `limit=1`, тот же индексированный путь.
- [Модель всё равно перескажет «0»] → Описание `search_operations` прямо
  говорит: если `outside_wallets.count` > 0, повтори без `wallets`.
