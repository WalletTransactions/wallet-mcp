# Proposal

## Why

На вопрос «Сколько я тратил на кафе летом и сколько зимой?» ассистент не знает, за какие годы смотреть. Локальная модель в LM Studio (`wallet-parse`) вместо вызова инструментов переспрашивает «укажите годы», хотя системный промпт с датой был задан. Claude Code сам выбирает период в 36 месяцев (с 2023-12-01 при данных с 2025-12) и получает `avg_per_month`, усреднённый по пустым месяцам: лето 81,19 € вместо 243,56 €, зима 15,89 € вместо 47,67 €. Сервер уже кладёт сегодняшнюю дату в `instructions`, но не знает и не сообщает, за какой период в леджере вообще есть операции, а часть клиентов (LM Studio) `instructions` модели не показывает.

## What Changes

- Новый read-only инструмент `ledger_overview()` без аргументов: сегодняшняя дата, период данных (дата первой операции .. сегодня, не длиннее 36 месяцев), число операций, валюты, кошельки, валюта по умолчанию и текст `hint` с готовым правилом «период не назван — бери `data_period`».
- Описания инструментов с периодом (`spending_by_category`, `spending_by_category_by_month`, `income_expense_by_month`, `search_operations`) начинаются с фразы «Период не назван — сначала вызови ledger_overview.». Описания доходят до модели в любом клиенте, в отличие от `instructions`.
- В `instructions` добавляется та же строка про `ledger_overview`.
- Новый эндпоинт в wallet-report: `GET /api/reports/data-range` (первая и последняя дата операций, число операций), потому что существующие эндпоинты отдают операции только по убыванию даты с курсором, и найти первую без обхода всех страниц нельзя.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `wallet-tools`: состав инструментов растёт с семи до восьми (девяти со справкой); новое требование `ledger_overview`; описания инструментов с периодом начинаются с отсылки к нему.
- `mcp-transport`: в `instructions` появляется строка про `ledger_overview`.

## Impact

- `wallet-mcp`: новый инструмент, правка описаний и `instructions`, строка в таблице инструментов `README.md`, юнит-тесты.
- `wallet-report`: новый эндпоинт `data-range` и запись в `openapi.yaml`; делается отдельным change в этом репозитории, wallet-mcp ждёт его.
- Остальные сервисы (google-auth, wallet-api, wallet-gateway, wallet-web, wallet-common) не меняются.
- Клиенты: никаких настроек, новый инструмент появляется в `tools/list` сам. Поведение существующих инструментов не меняется.
- Совместимость: эта правка нужна, чтобы демо-кадры LM Studio для страницы сайта (change `add-showcase-page` в wallet-site) показали ответ с суммами.
