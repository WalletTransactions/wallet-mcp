# mcp-access Specification

## Purpose
Кто и с какими правами вызывает MCP: каждый запрос аутентифицируется
персональным MCP-токеном пользователя, который сервис меняет в google-auth на
короткий read-only JWT для wallet-report и никогда не расширяет.

## Requirements

### Requirement: Токен в каждом запросе
Каждый запрос к `/api/mcp/`, включая `initialize` и уведомления, SHALL нести
`Authorization: Bearer wmcp_…`. Проверка выполняется до разбора JSON-RPC.
Cookie и другие источники токена сервис не читает.

#### Scenario: Без заголовка
- **WHEN** `POST /api/mcp/` с `initialize` без `Authorization`
- **THEN** ответ `401`, google-auth и wallet-report не вызываются

#### Scenario: JWT вместо MCP-токена
- **WHEN** `Authorization: Bearer <access-JWT веб-сессии>`
- **THEN** ответ `401`: токен без префикса `wmcp_` не принимается и в google-auth не отправляется

### Requirement: Обмен на JWT
Сервис SHALL получать JWT для wallet-report через google-auth
`POST /internal/mcp/token` с телом `{"token"}` (контракт — `openapi.yaml`
google-auth) и вызывать wallet-report только этим JWT. Сам MCP-токен в
wallet-report не уходит.

#### Scenario: Действительный токен
- **WHEN** запрос несёт действительный `wmcp_…`, кеша для него нет
- **THEN** сервис один раз вызывает `/internal/mcp/token` и выполняет запрос с полученным `access_token`

### Requirement: Кеш JWT
Полученный JWT SHALL кешироваться в памяти по SHA-256 MCP-токена и
переиспользоваться, пока до его `exp` остаётся больше 30 с. Сам MCP-токен в
памяти не хранится. При рестарте кеш пуст.

#### Scenario: Серия вызовов
- **WHEN** модель делает пять вызовов инструментов за минуту одним токеном
- **THEN** `/internal/mcp/token` вызван один раз

#### Scenario: JWT подходит к концу
- **WHEN** до `exp` закешированного JWT осталось 20 с
- **THEN** перед вызовом wallet-report сервис заново меняет MCP-токен

### Requirement: Отказ в доступе
Если токена нет, у него не тот формат или google-auth ответил `401`, сервис
SHALL ответить HTTP `401` с `Content-Type: application/json`, телом
`{"error":"invalid_token","message":"MCP-токен недействителен или истёк — выпустите новый в веб-кабинете: Настройки → Устройства"}`
и заголовком `WWW-Authenticate: Bearer`.

#### Scenario: Отозванный токен
- **WHEN** пользователь отозвал MCP-сессию в «Моих устройствах», кеш JWT для токена истёк, и клиент делает вызов
- **THEN** ответ `401` с этим `message`

### Requirement: Недоступный google-auth
Если google-auth не ответил (сеть, таймаут) или ответил кодом, кроме `200` и
`401`, сервис SHALL ответить HTTP `503` с
`{"error":"unavailable","message":"Сервис авторизации временно недоступен, попробуйте позже"}`
и не считать токен недействительным.

#### Scenario: google-auth перезапускается
- **WHEN** кеша для токена нет, а google-auth не отвечает
- **THEN** ответ `503`, а следующий запрос после подъёма google-auth проходит

### Requirement: Отказ wallet-report по токену
Если wallet-report ответил `401` на закешированный JWT, сервис SHALL выбросить
JWT из кеша, один раз заново обменять токен и повторить вызов. Повторный
`401` превращается в ответ `401` из «Отказа в доступе».

#### Scenario: Ключ google-auth сменился
- **WHEN** закешированный JWT подписан старым ключом, и wallet-report отвечает `401`
- **THEN** сервис меняет токен заново и повторяет вызов один раз

### Requirement: Нет параметров чужого доступа
Схемы инструментов SHALL NOT содержать `user_id`, `ledger_id`, `as_user_id`
или токена. Запросы в wallet-report сервис строит только из своих параметров
и аргументов по схеме инструмента. Лишние аргументы не пробрасываются.

#### Scenario: Prompt injection
- **WHEN** модель передаёт в `tools/call` аргумент `as_user_id`
- **THEN** ответ `-32602` (аргумент не по схеме), в wallet-report параметр не уходит

#### Scenario: Только свой леджер
- **WHEN** пользователь A вызывает любой инструмент своим токеном
- **THEN** все данные ответа — из леджера пользователя A
